【核心状态对象】
  globalConnectionState = {
    isConnected: false,       // WebSocket是否连接
    isRegistered: false,      // 是否已注册（收到clientId）
    clientId: null,           // 唯一客户端ID
    clientType: 'control',    // 'control' | 'display_a' | 'display_b'
    registerTime: null        // 注册时间
  }

【连接流程】
  1. initGlobalWebSocket() → SockJS连接 ✅
  2. onConnect() → isConnected = true ✅
  3. subscribeToAllTopics() → 订阅4个主题 ✅
  4. /app/register → 发送注册请求 ✅
  5. 收到client_registered → clientId = xxx ✅
  6. isRegistered = true ✅ 完全就绪

【重连策略 (指数退避)】
  快速重连 5 次：3s, 6s, 12s, 24s, 30s
  ↓ 全部失败
  定期重连：每 30s 尝试一次

【黄线代码 - 修改需谨慎】

  ⚠️ reconnectDelay (1000-10000ms)
  ⚠️ maxBackoffDelay (10000-60000ms)
  ⚠️ heartbeatIncoming (10000-30000ms)
  ⚠️ heartbeatOutgoing (10000-30000ms)

【快速诊断】
  问题              症状                      排查点
  ─────────────────────────────────────────────────
  连接失败          isConnected: false        后端是否启动?
                                            Vite代理配置?
  
  未注册            isConnected: true,       /user/queue订阅失败?
                   isRegistered: false       入站拦截器是否存在?
  
  消息收不到        已连接已注册             enhancedTimer.js订阅?
                   但屏幕无更新             后端是否发送状态?
  
  频繁断连          日志: 快速重连 1/5       心跳太短? 网络不稳?
  
  多个clientId      sessionId重复注册        映射检查是否删除?

【记住这三件事】
  1️⃣ globalConnectionState 是所有UI的源头
     任何删除都导致系统瘫痪

  2️⃣ ChannelInterceptor 是消息路由的关键
     删除后 /user/queue 消息无法送达

  3️⃣ sessionIdToClientId 映射防止内存泄漏
     删除后会导致多重注册
